# 原生數值與接觸合約（P1）

核心使用 Q32.32 int64；乘除採 signed 128-bit 中間值並向零截斷。
設定由 Python Fraction 精確轉換（最近值，半取偶數）。平方根整數向下取整。
沒有平台浮點三角函式；擊球方向使用固定 31 次 CORDIC 與版控常數，0° 為精確軸向。

每 tick 重力或滾動摩擦僅施加一次；之後按接觸時間切段。
`advance` 只回傳下一個場地接觸，外層可先插入更早的球棒／手套接觸。
`trace` 是可獨立測試的場地接觸協調器，不含比賽判決。
單 tick 上限 32 個接觸；超限明確拋出 `physics_contact_limit`。

掃掠時間為 [0, 2^32] 整數分數；最終事件寫入器須將 2^32 正規化為下一 tick 的 0。
AABB、接球圓柱與觸壘區含邊界。直線進入時間向下量化至 Q0.32，精確可表示切線保留原值。
圓弧出界時間採首次離開的整數時間（向上量化），避免反覆穿牆；反彈位置向場內解離 1 個 Q32.32 單位。
圓柱切線以 256-bit 無號乘積比較，保留 Q32.32 座標，不先降精度。
移動手套以球與球員相對掃掠判定；球員高度使用固定參數。

球員採每 tick 速度變化限制與速度上限。到目標觸碰區直接將速度歸零；非目標壘正常通過。
此層只回傳幾何候選，不判誰安全、封殺、得分或換局。
同時接球候選按 `(sub_tick_q, player_id)` 排序。其他規則同時事件由後續 Python 規則層處理。

本期獨立驗收無 Bot、無模型、無 Electron。Windows + Zig 0.13.0 已測試；尚不宣稱跨平台 D3。

P3 更新：若向下整數平方根造成正規化後超過速度上限，改用該根加一作分母；維持速度保守合法。
觸壘接觸時間仍向下量化，但硬停位置向區內解離最多 16 個 Q32.32 單位，避免量化後停在區外。
球員硬停／觸壘時間作為子段邊界，接球、封殺與觸殺均以分段相對掃掠計算。
事件 `(tick, 2^32)` 與候選得分時間均統一為 `(tick+1, 0)`。

P7 地圖更新：普通守備員的目標速度受 `sqrt(2*a*max(distance-radius,0))` 與最大速度共同限制，每 tick 再限制速度變化；不使用跑者目標壘的立即停下例外。目標與結果位於矩形可比賽範圍，公平區另限制於外野圓弧牆內。邏輯邊界碰撞以 Q0.32 二分找首次接觸並停止，提供子段終點時間。舊 map P4 的函式保持不變，依記錄版本明確分派。

原生建置目錄包含來源雜湊，避免新核心覆寫執行中程式載入的 DLL；每份建置 metadata 記錄來源、binary SHA-256、compiler version 與 flags。更新程式後，舊 viewer 應由使用者自行重新開啟。

## 2.0.0 平衡與記錄變更

2.0.0 封存時規則／物理／地圖為 2.0.0，詳細公式與參數見根 BALANCE.md。擊球初速上限 35 m/s 並受時機與 X–Z 接觸位置品質影響；力度越高甜蜜窗口越窄。跑者與守備使用各自速度／加速度；catch 半徑、相對速度控制與移動傳球誤差由 C++ 計算，dive 有持續與冷卻時間。快速投球有平方增加的決定性落點誤差。出手者在球離開最大接球區前不能自接。

新遊戲不分派舊規則，舊記錄 unsupported_version。TXT 使用同樣 Q32.32 整數，只保存觀看狀態差分；回放不重算物理。golden 由 regenerate_golden.py 明確更新，測試不會自行改寫期望值。

## 2.1.0 守備時間成本

接球以子 tick 接觸點停止守備員並將速度歸零；恢復截止為接球 tick + ceil(sub_tick) + catch_recovery_ticks。恢復截止 tick 才能再提交移動／傳球。接受 throw 後停在原地，t + throw_windup_ticks 出手；期間不能重啟、更換方向／力度或以 hold 取消準備。跑動誤差使用啟動準備時的速度；實際出手時才快照傳球出場授壘所用的合法壘位。死球／失去持球權取消準備。

持球移動上限以原生 Q32.32 乘法計算 fielder_speed_q × held_speed_multiplier_q；仍用同一 C++ 移動、加速、煞車與場地掃掠。其他人與跑者繼續正常推進，不因守備員準備傳球而暫停模擬。計時狀態與待出手動作納入 snapshot／雜湊、Bot 公開觀察及 TXT 差分。

舊 2.0.0 記錄為 unsupported_version；可使用 balance-v2.0.0／launcher-v1 等原版本 checkout 觀看。新 golden 增加接球恢復→延後出手的完整狀態／事件軌跡。參數與達標結果以 BALANCE.md 掃描報告為準。
